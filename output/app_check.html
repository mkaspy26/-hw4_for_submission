1. Chat checks the inventory level of an item PASS

On the Products page I asked Sir Handsome Dan, the shopping assistant, about stock and price for one product, then a follow-up about a sold-out size.

Verified against the database

QueryResultChat said
SELECT price FROM catalogue WHERE product_id='fencing-left-chest-hoodie'68.0$68 ✅
SELECT size, quantity FROM inventory WHERE product_id='fencing-left-chest-hoodie'XS=0, S=12, M=15, L=0, XL=2, XXL=0"Only 2 … in XL" ✅ · "L is sold out" ✅ · "in stock in S, M, XL" ✅

How it stays honest: the agent must call check_stock / get_price (DB tools), and output validators reject any $ amount or stock count that no tool returned that turn (see output/harness.md §4.2 and output/usability.md B2).

2. Dynamic search-result cards after a category question PASS

Starting on the Home page, I asked the chat a category question. The site moved to the Products page and showed the matches as product cards.

Verified against the database

QueryResultSite showed
SELECT COUNT(*) FROM catalogue WHERE garment_type||name LIKE '%hood%'27"27 hoodies", 27 cards ✅
SELECT DISTINCT price FROM catalogue WHERE … LIKE '%hood%'45, 68, 88"most are $68, with select styles at $45 or $88" ✅

How it works: the agent returns {message, product_ids, results_heading}, and the backend turns the ids into DB product cards in page_results, which the front end renders (harness §2.1 and Appendix A5).
